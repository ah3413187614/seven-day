# 分支设计与路线阅读

## 节点与路径不是同一个数量

第一日1个节点有4个行动；第二日有4个节点共16行动；第三到七日各16个基础节点共64行动／日。另有4个由关键前史触发的第七日节点。每局仍只经过7个节点，作7次行动，共16384条输入序列。

前一日的每个菜单指向四个不同处境。例如在“山路朝着身后”：折返去民兵、继续前行去离群处境、申请收容去教会、引水去遗迹研究。次日不是同一个救人与杀人问题换四句台词。

## 第一、二日入口

| 第一日 | 第二日 | 四种可以真正做的事 |
|---|---|---|
| 响应召集 | 粮单与冠冕 | 签征召换粮／核军粮账／公开被弃村名／护送难民 |
| 调查教会 | 钟楼下的删文 | 立誓进钟楼／抄病历换禁页／公开审信使／收留两族伤兵 |
| 进入旧林 | 没有守卫的剑 | 拔圣剑／测绘管道／夺炉芯／转移龙卵 |
| 留守故乡 | 桥只够过一辆车 | 组民兵／造渡船／带家人撤离／照护不能走的人 |

## 收拢规则

同一基础处境可以有多种来路；路由不会反向删除事件。历史差异通过三层保留：顶部即时展示昨日后果；重大物品／伤害开启独立终局；结局用全七日轨迹与不可撤销旗标判定。

收拢后的普通节点不保证所有早期flag都改写四个按钮。这个边界是主动内容预算，而非无限四叉树的宣传。优先扩展具有明显能力差异的前史，避免每个无关小事都复制完整菜单。

## 人类与程序如何查图

完整逐节点资料在story_reference.md，每个行动写明原始ID与目标。edges.csv列出所有显式转移。story.json中的variants记录基础目标被前史条件替换的分支；不能只读CSV后误认为变体无入口。

branches_by_day.md是从实际数据生成的逐日转移表，可以按“节点→四项行动→下一节点”连续追踪。tests/witnesses.json为每个可触发称号提供完整七次choiceId，供测试复现；它是策划剧透，不在游戏内展示。
