# 结局引擎说明（DESIGNER_ONLY）

代码入口：src/engine.js 的 finish。原始规则：data/endings.json；弧光：data/arcs.json。可复现见 tests/witnesses.json。结局完全确定性，不调用模型、随机数或网络。

## 算法

1. 确认七次合法选择，取得最后行动给出的真实身份。身份包含救世主、勇者、容器、守护者、国王、教会领袖、弑神者、远行者、普通人、殉道者、流亡者、暴君、见证者、摆渡人、养龙人、失控者。
2. 累积前六日数值，选择最高人格；同分时较早出现的相关行动优先，再按固定维度顺序。最后一个按钮不能独自洗掉此前人格。
3. 检测人物轨迹：前1—3日至少一次早期取向，后5—7日至少两次后期取向，另核验身份与指定事件出现的时间。命中多弧光时按专属优先级、稳定ID排序。所有命中弧光仍返回证据，即使主标题只采用一个。
4. 有重大罪责时，普通称号替换为罪责称号。明确描述堕落／赎罪的弧光和暴君类称号可以保留，但后日谈必须列出罪责，不宣称获赦。
5. 无罪责时检查作者写定的特殊条件；特殊称号覆盖常规弧光，不进行任意字符串拼接。
6. 真结局最后检验：至少通关一次；lattice_validated、shared_load、collective_final都为真；无重大罪责或强征。成功才结束单一容器制度。
7. 根据真实角色死亡、容器是否释放、六方关系、最后行为组装尾声。龙被杀就写已死；艾德里安停止承压就明确死亡；殉道者不能在个人尾声回家种田。
8. 展示称号、世界结果、人物后日谈、个人余波、最后一句、七日回顾。记录图鉴，同一局刷新不重复计通关。

## 合法性与组合

基础称号是16身份×8人格共128条逐项写定的白名单，而非任意组合。例如“仍然祈祷的弑神者”具有角色逻辑，“温柔的暴君”明确是曾想照护人、最终剥夺拒绝权的矛盾人格，绝不写成无害的仁慈君王。

另有16罪责规则、24弧光规则、8特殊规则，总计176候选条目。部分普通称号必然被更明确的特殊标题覆盖，或在当前路由中没有相应人格组合；构建将其标为设计储备，玩家图鉴只统计穷举证明可达的规则。不能把176候选当作176可收集称号。最终数量见tests/report.json及docs/qa_report.md。

“同世界结果不同人格评价”和“不同世界结果”分别计数。游戏有16种终局身份与额外真结局状态，不宣称有一百多种完全独立的世界毁灭／获救方式。

## 弧光示例与限制

coward_to_brave：早期逃离或继续撤离，后期返回并至少两次勇气行动，身份为勇者／守护者。不能把任何一次自由行动都判断为懦弱。

selfish_to_selfless：早期野心取向、末三日至少两次牺牲、最终身份可承接。它记录选择重心的变化，不诊断真实玩家的人格。

merciful_to_cruel：早期照护、后期至少两次堕落行动，加上具体伤害事件。早先的善举变成轨迹的一部分，不作为抵扣券。

cruel_to_redeemed：早期吞灰／吸收深渊、后期实际停止或交还力量并以照护为连续行动；标题描述接受监督，尾声仍保留所有罪责。

其他20种均写在arcs.json，可读取条件和穷举见证。当前阈值是可验证的策划第一版，不是经过用户研究验证的心理量表。

## 重大罪责

包括处决未受审少年、杀无辜者、牺牲无辜街区、强制征集承压者、强制接入、让陌生人替熟人承担压力、把恐惧作为强制燃料、奴役核心。屠龙作为独立物种／政治伤害永久记录，并触发专门问责场景；不把它简单等同于所有语境中的谋杀。

拯救大陆、成为宗教领袖或牺牲自己都不能删去罪责旗标。归还物品也不删除曾经抢夺的历史。没有“Mercy够高即清空罪行”的规则。

## 重点尾声的使用

docs/ending_texts.md给出24份正式编辑稿。16身份稿作为世界／语气基础，8特殊／弧光稿提供重点覆盖。实际程序优先保证事实一致：NPC段落根据状态重写，普通身份段落绑定实际最后行动和第一日选择；不能无条件把所有前辈写成得救，把所有同伴写成原谅。

后续值得优先补写的是“身份×重大前史”的文学化中段，当前版本已有精确证据和条件逻辑，部分动态过渡文字仍偏功能说明。不要为了修辞牺牲状态事实。
